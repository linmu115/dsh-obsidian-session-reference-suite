# DSH–Obsidian 桥整合实施计划

2026-09-18，用户明确授权按已讨论需求开始施工。此前“等待开工”约束已满足。本计划的各阶段按顺序验收；后续专门笔记、模板、样式和面板操作通道不在本次施工范围。

前三阶段已完成桥内部能力的本地源码、构建与合成验收，见[原阶段记录](changes/2026-09-18-binding-scope-delivery.md)。用户随后确认交付形态必须收敛为一个桥插件，旧 Suite wrapper 方案被取代。当前补充阶段见下文与[单桥更正记录](changes/2026-09-18-single-bridge-product.md)，不得把原阶段结果当作新包或安装验收。

## 第一阶段：整合已有能力

1. 将独立 Reference Adapter 的宿主与浏览器接入并入桥。初阶段保留旧包名的方案已由补充阶段取代：产品名改为 `dsh-obsidian-bridge`，旧内部 `obsidianBridgeLifecycle` 服务名保留兼容。桥对外提供连接、消息分派、引用交接及健康信息；Core 保留引用状态、提交、补偿与持久任务。
2. 原阶段曾把 Adapter 保留为兼容入口、由 Suite 加载三个运行组件；该安装方案已退役。当前 profile 独立加载 Core、Bridge、Sticker 各一次，旧 Adapter 和 Suite 不再是安装成员；服务晚加载不能重复注册来源、消费动作或轮询。
3. 普通贴纸保留笔记关联界面、业务校验和数据。它通过共享通道请求引用和注册已有定位处理器，不再拥有一套桥连接或独立消息轮询。
4. Bridge 自主管理通用连接维护信息。贴纸仍可展示业务同步状态，但不是唯一的桥维护入口。
5. 保留现有 Maintenance 数据归属、会话解析、引用定位和迁移冻结流程。没有可选插件时，独立能力继续运行；已纳管数据不能退回旧副本写入。

验收：动态 Web 端口与已鉴权 Viewer 地址仍来自实际运行实例；选段只投递目标内嵌页面；引用领取幂等、冲突补偿、停止后重连、删除任务、逻辑会话定位保持；普通贴纸本地编辑与关联引用保持；新旧入口并存不重复执行。采用内存存储、合成 HTTP 服务和临时目录，不对真实 Vault／会话执行测试写入。

## 第二阶段：两侧绑定与路由

第一阶段组合验收通过后，才在 DSH Bridge 与 Obsidian Bridge 实施一 Vault 至多一实例、一实例多 Vault。稳定实例身份与每次启动的端口分离。桥拥有有效绑定和路由，维护插件通过桥管理。发现来源先核验现有 Launcher 与宿主身份，再实现自登记及人工配对；Launcher 为可选来源。

同实例 Vault 共用实例勾选的同步工作区范围。取消同步保留历史链接，清楚区分未同步、离线、映射未就绪及会话删除；重新同步后验证原身份再恢复。改绑只影响后续操作，既有引用和排队操作不得改投新实例。

## 第三阶段：维护扩展接入

用户在施工核查中新增授权：Maintenance 自己提供每个 DSH 实例的工作区同步选择，只有选中工作区内容参与实例与真源的双向同步。该能力是有效范围的唯一策略来源；与 Codex 来源导入选择分开。在后续桥绑定完成后，先实现并验收范围存储、设置界面、出站投影与入站回收过滤，再让桥和信息页消费同一结果。用户随后确认：这里指 Maintenance 的会话分类工作区，保存后在实例下次启动时生效。当前运行固定使用启动时的范围，允许正在进行的会话完成保存；下一次运行使用新范围。实际回写须在事务内核验该运行的有效范围和当前会话归属。撤销范围不能被解释为删除真源。

在可用的桥绑定接口上，增加 Maintenance 业务扩展注册和插件信息页。数据目录是可复用栏目，插件可提供自身栏目。宿主聚合完整插件名单，避免各插件单独连接时互相覆盖登记；DSH 版本 Adapter 继续只负责宿主会话格式。绑定页和 Adapter 不接管普通贴纸业务。

本阶段验收包含 Maintenance 单独安装、桥系列单独安装和组合安装。有效同步范围必须读取真实实例同步权威来源，不增设另一份勾选名单。

## 补充阶段：单一桥插件产品与安装验收

- 发布候选产品名 `dsh-obsidian-bridge@0.4.1-rc2.1`；旧 Lifecycle 物理仓库路径保留历史，运行身份不再暴露成另一个安装项。
- Suite 转私有开发/文档/组合验收工作区，删除运行父组；旧 Adapter 不进入当前候选安装，Protocol 由消费者内部依赖。
- Core `0.3.12-rc2.19`、Bridge、Sticker `0.7.4-rc2.3` 在 profile 独立加载一次，验证缺席、晚加载及卸载；Maintenance 独立可选。
- 重建实际包组并核验 metadata、客户端资源和安装登记。部署后单独核验宿主探针、无重复注册、原身份/数据保留及双应用窗口行为，逐项填写验收记录。
- 未来专用通道归同一 Bridge 产品；本轮不实现任意笔记、模板或样式业务。
